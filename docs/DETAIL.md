# API 消耗确认（API spend gate）

在 DSH 里，模型推理和工具调用可能消耗你的账户余额。这个插件在**会发起额外模型推理或外部付费调用**的工具执行前，用系统自带的审批弹窗让你点一次「允许」，避免意外扣费。

## 行为

- 拦截 `tools/pre-execute`，命中受管工具时先不执行，而是走 DSH 的审批通道（`ctx.approval.request`）。
- 弹窗批准后记为**本轮已授权**：从当前用户消息到下一次用户消息之间，后续同类工具调用直接放行，不再重复弹窗。
- 用户下一次发言后授权自动失效，新一轮再次询问。
- 用户拒绝、取消，或审批通道不可用时**一律拒绝执行**（fail closed），模型会收到明确的拒绝说明，不会擅自重试。

## 默认受管工具

| 工具 | 为什么要拦 |
|---|---|
| `subagent` / `subagent_fork` | 派生子 Agent 会发起一整段额外模型推理，是余额消耗的主要放大器 |
| `workflow` | 会派出多个子 Agent 并行工作 |

## 配置

在 `cordis.patch.yml` 的 `config.tools` 里增删受管工具即可，例如把外部检索也纳入：

```yaml
config:
  tools:
    - subagent
    - subagent_fork
    - workflow
    - web_search
    - web_fetch
```

> 提示：子 Agent 通常没有自己的浏览器审批界面；如果把 `web_search` 这类子 Agent 也会用到的工具纳入，子 Agent 内部的调用可能因审批无人应答而被拒绝。若出现这种情况，把该工具从列表移除，或只在顶层使用。

## 已知限制

- 审批依赖 Agent 作用域的 `approval/request` 通道；没有可用答复方时一律拒绝（安全优先）。
- 「本轮」以会话的 `turn` 计数为准；同一条用户消息内多次调用共享一次授权，新消息会重置。
- 插件只拦工具调用这一层，不改变模型本身的基础推理开销。
